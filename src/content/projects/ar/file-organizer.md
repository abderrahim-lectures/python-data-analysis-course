# 📁 ابنِ روبوتًا لتنظيم الملفات

مجلد ترمي فيه الأشياء منذ سنة: لقطات شاشة، وملفات PDF، وبعض الأرشيفات المضغوطة، وملفات موسيقى محمّلة، وثلاثة سكربتات، وملف بلا امتداد. يمكنك ترتيبه يدويًا في عشرين دقيقة، أو تكتب ما يرتبه، فلا تفعلها يدويًا مرة أخرى.

هذا أول مشروع يلمس نظام ملفاتك الحقيقي، وهذا يجعله معلمًا أفضل مما يبدو: نقل الملفات عملية مُتلفة، وبرنامج مهمل في هذا الجانب أسوأ من عدم وجود برنامج. لذلك يُبنى الروبوت كما تُبنى أدوات التعامل مع الملفات فعلًا: يخطط أولًا، ويطبع الخطة، ولا ينقل إلا بطلب منك، ويسجّل ما نقله، ويستطيع التراجع عن آخر تشغيل.

## 🎯 ما ستفعله

1. تفحص مجلدًا وتصنّف كل ملف حرّ بحسب امتداده إلى فئة.
2. تبني **محاكاة**: تحسب كل عملية نقل، وتطبعها، ولا تلمس شيئًا.
3. تنفّذ عمليات النقل مع معالجة تعارض الأسماء بدل الكتابة فوقها.
4. تكتب سجل عمليات، وتعيد تشغيله بالعكس للتراجع.
5. تختبر كل ذلك على مجلد نموذجي مبعثر عمدًا، لا على مجلدك الحقيقي.

## أين تشغّله

**محليًا باستخدام `uv`.** المشروع يستخدم مكتبة بايثون القياسية فقط — `pathlib` و`shutil` و`json` — فلا شيء تثبّته، لكنه يجب أن يعمل على جهازك لأنه يلمس ملفات حقيقية.

```bash
cd examples/file-organizer
uv run python generate_sample.py          # ينشئ مجلدًا آمنًا للتجربة
uv run python organizer.py sample_messy_folder --dry-run
uv run python organizer.py sample_messy_folder
uv run python organizer.py sample_messy_folder --undo
```

الشيفرة التنفيذية الكاملة في [`examples/file-organizer/`](https://github.com/abderrahim-lectures/python-data-analysis-course/tree/main/examples/file-organizer).

## الخطوة 1 — التصنيف بحسب الامتداد

الروبوت كله يقوم على دالة صغيرة: من الامتداد إلى الفئة.

```python
CATEGORIES = {
    'documents': {'.pdf', '.txt', '.doc', '.docx', '.csv'},
    'images': {'.png', '.jpg', '.jpeg', '.gif', '.svg'},
    'archives': {'.zip', '.tar', '.gz'},
    'code': {'.py', '.js', '.ts', '.sh'},
    'audio': {'.mp3', '.wav'},
    'video': {'.mp4', '.mov'},
}
```

ما ليس في القائمة يذهب إلى `other`. هذا الاحتياط مهم: امتداد مجهول لا يمكن أن يُسقط الروبوت أبدًا، والملف بلا امتداد (`mystery`) يُصنَّف عمدًا لا بالمصادفة.

## الخطوة 2 — التخطيط قبل النقل

تحسب المحاكاة قائمة بأزواج `(المصدر، الهدف)` وتطبعها. لا شيء يتغيّر على القرص.

```
[DRY RUN] No files will be moved. Target: sample_messy_folder

Planned moves (10):
  notes.txt      ->  documents/notes.txt
  photo1.jpg     ->  images/photo1.jpg
  report.pdf     ->  documents/report (1).pdf
  mystery        ->  other/mystery
```

هذا `report (1).pdf` ليس خطأ: المجلد النموذجي يحتوي بالفعل على `documents/report.pdf`، فأول تشغيل يمارس معالجة التعارض الحقيقية.

## الخطوة 3 — تعارض الأسماء، لا الكتابة فوقها

`shutil.move` الساذج سيكتب فوق الملف الموجود ويضيعه. يضيف الروبوت `(1)` و`(2)` حتى يخلو الاسم، وهو العرف نفسه الذي يستخدمه مدير ملفاتك، وللسبب نفسه.

## الخطوة 4 — سجل يمكن إعادة تشغيله بالعكس

كل تشغيل حقيقي يضيف إلى `.organizer_log.json`: المصدر والهدف والطابع الزمني. يقرأ `--undo` مدخلات آخر تشغيل ويعيد كل ملف إلى مكانه، من الأحدث إلى الأقدم.

هذا هو الفرق بين سكربت وأداة. سكربت ينقل الملفات ولا يستطيع التراجع يبعد عن خطأ مطبعي واحد من أصيلة سيئة.

## الخطوة 5 — اختبر على شيء آمن

يبني `generate_sample.py` مجلدًا مؤقتًا فيه تعارض متعمّد وملفات بلا امتداد وملف مخفي يجب أن يتجاهله المنظّم. شغّل الروبوت هناك أولًا، دائمًا. العادة هي الدرس: المحاكاة موجودة لأن توجيه شيفرة تنقل الملفات إلى `~/Downloads` في المرة الأولى هو كيف يفقد الناس بياناتهم.

## 🤔 أسئلة سقراطية

- لماذا يستحق وضع المحاكاة كتابته وأنت تستطيع ببساطة أن تكون حريصًا؟
- ماذا ينبغي أن يحدث إذا كان مجلد الهدف موجودًا لكنه ملف؟
- هل ينبغي أن يرفض `--undo` العمل إذا تغيّر ملف منذ نقله؟ ولماذا؟
- ما أصغر نسخة من هذا الروبوت ما زلت تأتمنها على مجلدك؟
