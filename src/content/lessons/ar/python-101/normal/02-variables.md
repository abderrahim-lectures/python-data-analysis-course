## لماذا تحتاج القيمة إلى اسم؟

اكتب برنامجًا يحسب متوسط ثلاث درجات اختبار:

$$
\bar{x} = \frac{7.5 + 8.5 + 9.0}{3} = \frac{25.0}{3} \approx 8.33.
$$

وافترض الآن أن الدرجات تغيّرت — يريد المعلم متوسط $9.5, 8.5, 10.0$. دون أسماء، يظهر تعبير المتوسط في عدة مواضع ويجب أن تبحث عن كل واحدٍ وتعدّله بيدك. تلك وصفة لأن يَسقط أحدها.

يحلّ الرياضي هذه المشكلة *بتسمية الكميات*: اكتب $x_1, x_2, x_3$ مرة واحدة ثم أحل إلى أيٍّ منها متى شئت. للبرنامج الحاجة نفسها: تظهر القيم مرارًا وتكرارًا، ويجب على الآلة أن تجد القيمة الحالية في كل مرة. جواب بايثون هو **المتغير** — اسمٌ يشير إلى قيمة. بمجرد أن يسمّي `score1` القيمة $7.5$، يمكنك كتابة `score1` أيّ عددٍ من المرات، وتبحث بايثون عن قيمته الحالية في كل مرة.

## `=` يربط اسمًا بقيمة

في الرياضيات، «ليكن $x = 5$» يثبّت الرمز $x$ على العدد $5$. تفعل بايثون الشيء نفسه وبنفس الرمز تمامًا:

```python
score1 = 7.5
score2 = 8.5
score3 = 9.0

average = (score1 + score2 + score3) / 3
print(f"{average:.2f}")    # 8.33
```

يُقيَّم الطرف الأيمن *أولًا*، وبعده فقط يبدأ الاسم في الطرف الأيسر بالإشارة إلى النتيجة. إذا غيّرتَ الدرجات وأعدتَ تشغيل الملف، سيستخدم الحساب نفسه القيم الجديدة — إذ تعطي الأسماء للآلة موضعًا تبحث فيه عن «القيمة الحالية لـ $7.5$».

## الأسماء قابلة لإعادة التوجيه

هنا لا يُشبه المتغيرُ الرمزَ الرياضي. في الرياضيات، $x = x + 1$ جملة بلا حل. أما في بايثون فهي تعليمة عادية تمامًا، تُقرأ من اليمين إلى اليسار:

$$
x_{n+1} = x_n + 1
$$

تعني «القيمة التالية لـ $x$ هي قيمته الحالية زائد واحد». بمجرد أن ترى هذا في بايثون، فأنت تعدّ:

```python
count = 0
count = count + 1    # قُرئت القيمة القديمة 0، حُسب 1، والاسم يشير الآن إلى 1
count = count + 1    # الآن count يسمّي 2
```

إعادة الإسناد هي *إعادة توجيه تسمية*، لا ملء صندوق. القيمة القديمة لا «تتغيّر» ولا «تُستبدل» — الاسم ببساطة ينظر إلى قيمةٍ أخرى الآن.

## القراءة-التحديث-التخزين حركةٌ واحدة: `+=`

النمط السابق — اقرأ `count`، أضف `1`، وجّه `count` نحو النتيجة — شائعٌ لدرجة أن بايثون اختصرته. قل إن خطوةَ الانتقال $h$ وأنت تتنقل في متتابعة عامة:

$$
x_{n+1} = x_n + h.
$$

على الورق، تكون التحديث `x = x + h`. تدمج بايثون القراءة والتخزين في عامل واحد:

```python
x = 5
x += 1     # مثل x = x + 1 تمامًا   -> 6
x -= 2     # مثل x = x - 2 تمامًا   -> 4
x *= 3     # مثل x = x * 3 تمامًا   -> 12
x /= 4     # مثل x = x / 4 تمامًا   -> 3.0
```

اقرأ `x += h` بصوتٍ عالٍ بمعنى *«قدّم x بمقدار h»* — حركة واحدة، كما تفعل المتتابعة.

## اسمٌ يمكنك التلفظ به

أي كلمة تقريبًا تصلح اسمًا، لكن *الصحة* ليست *الجودة*. أيّهما أوضح عند قراءة برنامج نتيجتك؟

```python
x = 87.5                 # يسمّي عددًا، لا شيء أكثر
quiz_score = 87.5        # يسمّي الكمية
```

قواعد قليلة وعادة واحدة:

- يبدأ الاسم بحرفٍ أو شرطة سفلية، ولا يجوز أن يحوي بعدها إلا الحروف والأرقام والشرطات السفلية — `second_score` ✓، `2nd_score` ✗.
- اصطلاح بايثون هو **snake_case**: كلماتٌ صغيرة الحروف تُوصل بشرطة سفلية، مثل `student_name` لا `studentName`. وهو يطابق طريقة النطق: `quiz_score` هي درجة الاختبار.
- مجموعة صغيرة من الكلمات **محجوزة** — `if`, `for`, `class`, `True`, `False` — ولا يصح استعمالها أسماءً.

ستعيد قراءة كودك أكثر مما تكتبه؛ الاسم الذي تختاره حين تكتب هو ما يعيد المعنى إليك عند القراءة لاحقًا.

## مثالٌ محلول: المجموعُ المتصاعد

ينفعُ إعادةُ التوجيهِ حين تُبنى كمّيةٌ خطوةً خطوةً — المتتاليةُ $x_{n+1} = x_n + h$ والمجموعُ الجاري هو $x_n$:

```python
total = 0
total += 8.5     # يصير total = 8.5
total += 9.0     # ثم 17.5
total += 10.0    # ثم 27.5
average = total / 3
print(f"{average:.2f}")   # 9.17
```

كلُّ `+=` يتقدم خطوةً: يقرأ القيمةَ الحاليةَ، فيجمعَ، ثم يعيدَ توجيهَ الاسمِ نحو النتيجة. يُبقي الاسمانِ `total` و`average` الكميتينِ منفصلتينِ، فيُقرأ الدليلُ كما يصفُ.

## أخطاء شائعة

- **استخدام كلمة محجوزة اسمًا.** `class = "Math"` يرفع خطأ `SyntaxError` — `class` محجوزة.
- **البدء برقم.** `2nd_place = "B"` غير صالح؛ `second_place = "B"` صحيح.
- **الخلط بين `=` و `==`.** `=` يوجّه اسمًا نحو قيمة؛ أما `==` فيسأل هل القيمتان متساويتان. زلة حرفٍ واحد تحوّل جملةً خبرية إلى سؤال.
- **يكتب `+=` على اسمٍ يجب أن يكون موجودًا بالفعل.** يرفع `total += 1` على اسمٍ لم يُسنَد قطُّ خطأَ `NameError`. فالإيماءةُ تقرأ القيمةَ الحاليةَ أولًا؛ والاسمُ بلا قيمةٍ لا شيءَ ليقرأه.

## 🤔 أسئلة سقراطية

- لماذا تختار بايثون `snake_case` بدلًا من `camelCase`؟ ماذا توحي شرطة السفلية بصريًا عن طريقة قراءة أسماء المتغيرات؟
- `x += 1` و`x = x + 1` ينتجان النتيجة نفسها للأعداد. هل ترى سببًا يجعل لغةً ما تعرض الصيغتين معًا؟
- إذا كانت المتغيرات *تسميات لا صناديق*، فماذا يحدث عند كتابة `a = [1, 2, 3]` ثم `b = a` ثم `b.append(4)`؟ هل يرى `a` العدد `4`؟ (جرّب — هذه لمحة عن الكائنات القابلة للتغيير، تُشرح لاحقًا.)
