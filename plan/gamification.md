# Gamification (single-model, no mode toggle)

Gamification is one model baked into `src/lib/gameState.ts` and rendered (without hiding) from the same data everywhere. There is **no Gamified/Classical mode toggle** in the Astro build (the Docusaurus-era `ModeToggle`/`UiModeContext`/`BadgeCase`/`BonusContent` unlock gating was dropped), and no per-feature per-page keys — everything lives inside the single `pda:state` blob (see [`persistence.md`](./persistence.md)).

- **XP economy** (`src/lib/gameState.ts` constants): `LESSON_COMPLETE` 60, `LESSON_RUN` 5, `PROJECT_VIEW` 5, `PROJECT_STEP` 15, `PROJECT_COMPLETE` 100, `QUIZ_CORRECT` 5, `QUIZ_PERFECT` 25, `DAILY_LOGIN` 5, `STREAK_BONUS` 15, `STREAK_MILESTONE` 30, `MILESTONE_XP` 25, `CHALLENGE_COMPLETE` 15. XP is not capped; ranks top out at Grandmaster (9999 XP).
- **Badges** are a flat `badges: string[]` in state (e.g. `markQuest()` appends a label like `🏅 Week 1 complete`). They are earned via quests (`quests: Record<string, boolean>`) and milestone evaluation (`evaluateMilestones`, `awardDailyLogin`), not via a separate per-mode render path.
- **Quests** (`quests: Record<string, boolean>`) and the **activity log** (`activityLog`, capped at the last 200 entries; event types `lesson-run`, `lesson-complete`, `quiz`, `project-view`, `project-complete`, `daily-login`, `streak`, `milestone`) are what the `/progress` page renders — a transparent "player card" (rank, XP bar, streak, quests progress, project stats, action log) rather than a hidden leaderboard.
- **Streaks**: `streak`, `bestStreak`, `lastActive`. The code carries a repair path for pre-rebalance states that "shipped a streak that could never leave 0 and never awarded the milestone quests" — legacy learners keep their real XP but get quests/milestones backfilled.
- **On-site UX**: the only standalone gamified UI is the onboarding dialog (gated on `pda:onboarded`, once per visitor) plus toast/XP indicators on lesson quiz/run completions. No unlock machinery and no bonus-content gating — content is free to read, gamification only *marks* progress (and earns XP on the way), it never gates access.
- **Styling**: gamified flourishes (emoji icons, badges, `.badge--*` treatments, streak accents) are pure CSS in `src/styles/global.css` — visible to every visitor, no `body[data-ui-mode]` switching layer.
