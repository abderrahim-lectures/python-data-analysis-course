# Code Organization & Engineering Practices

At the current scale (Astro pages + components, three content collections, a client-side Pyodide runtime, i18n, and a single-blob game-state engine), a few practices keep things manageable:

- **Small, single-responsibility files, idiomatic Astro**: specific `.astro` components live under `src/components/` (layout-level in `src/components/projects/`, `src/components/learn/`, etc.); `.astro` files keep view concerns and delegate behavior to plain-TS modules under `src/lib/`. Client-side logic that must run in the browser lives in `*.client.ts` / `*.mjs` (e.g. `runnable-cell.client.ts`, `projectsRender.ts`) rather than in globals.
- **Cross-cutting state centralized once**: all progress/XP/badge/streak/quest/activity-log logic is one module, `src/lib/gameState.ts`, over the single `pda:state` key (see [`persistence.md`](./persistence.md)). i18n strings are centralized in `messages/{en,ar,es,fr}.json` (compiled by Paraglide into `src/paraglide/`) plus `src/lib/routeSegments.ts`, and strict key-parity across locales is enforced by `tests/unit/i18n.test.ts`. Build-time content transforms live as rehype plugins in `src/lib/` (`rehype-runnable-python`, `rehype-section-blocks`, `rehype-drop-leading-h1`, `rehype-fix-docs-links`).
- **Shared types live where they're read** (opencode convention): content collection schemas are zod in `src/content/config.ts`; route helpers (locale → URL words) in `routeSegments.ts`; no sprawling cross-referenced `types/` tree.
- **Testing is first-class, not bolted on**: unit suites under `tests/unit/` (content schema, game-state, i18n parity, JSON-LD, wiring, link/path helpers, Python-guard) and CDP e2e drives under `tests/e2e/`. Details and run commands in [`testing-and-verification.md`](./testing-and-verification.md).
- **This fits the Development Workflow's per-component issue granularity**: focused files map onto small, focused PRs — a component already split into view + lib + test layers is easier to review and land incrementally than a monolithic file touched by every related PR.
