# Real-World Projects (content-collection catalog, no completion gate)

The "Capstone" framing from the Docusaurus era (`docs/projects/`, `CapstoneChooser`, `_category_.json`, `sidebars.ts`, `mergeProjectMeta`, `CapstoneProgressCheckbox`) is **gone**. Projects are now a content collection with a catalog UI, structured differently:

- **Content location:** `src/content/projects/*.md` are the EN originals; locale translations live in `src/content/projects/{ar,es,fr}/` (full per-locale copies). A Markdown frontmatter block carries `title`, `description`, `slug` (legacy `/projects/<name>`), `difficulty`, `estimatedMinutes`, `xpReward`, `tags`, `learningObjectives`, `prerequisites` — i.e. *content only*. No `id`/`date`/`url` structural metadata file; the catalog sorts/filters derive directly from the collection's frontmatter.
- **Catalog UI:** `/projects` renders `ProjectListing` (shared component; `src/pages/projects/[...slug].astro` renders `ProjectDetail`). The index supports **live search** (client-side `projectsRender.ts`, delta against a haystack of title+description) and **tag/difficulty filters**, each state synced to the URL query string (e.g. `?q=wordle`, `?tag=AI+Agents`) so filtered views survive reload; the grid is virtualized on narrow viewports. Search/filter flow is regression-tested in `tests/e2e/smoke.mjs`.
- **No unlock gate.** Project pages are freely browsable and linkable. `ProjectDetail` runs the same client-side wiring — step-clearing (`projectsSteps`), `project-view` XP (`+5`), `project-complete` (`+100`) — that the lessons use, but nothing is locked. Each project states its prerequisites in frontmatter prose.
- **Per-project progress:** `projectsViewed` / `projectsCompleted` / `projectsSteps` maps (keyed by slug) in `pda:state`, same single-blob persistence as everything else.
- **Example code / notebooks:** `examples/<slug>/` holds runnable project code; many projects also ship a notebook, opened via the `NotebookCell`-style Colab/Kaggle/Binder/nbviewer/Deepnote/GitHub badges (see [`playground.md`](./playground.md)). No `requirements.txt` union pre-install in this architecture; the notebooks reference their own deps inline.
- **Project-visible identity:** oldest slug ids (`ai-agent`, `finetune-llm-unsloth`, `mcp-server`, `agentic-code-reviewer`) carried over from the redesign — there were no year-prefixed ids in production to preserve, so the catalog is slug-based and slots right back into `/projects/<slug>` URLs.
- **Maintenance policy — frozen except critical fixes:** shipped project content stays as written; broken links/dead APIs/security issues get patched via the normal issue→branch→PR flow. A newer approach to the same theme is a new project, not a rewrite of an old one. Adding a project = drop a `.md` in `src/content/projects/` (+ translated copies) — no sidebar/catalog metadata files to keep in sync.
- **Why this fits:** a discoverability/marketing surface for visitors landing on `/projects` before starting the course, and the natural "install Python for real" graduation step that pairs with finishing a section. No completion gate means it doubles as the front-door showcase.
