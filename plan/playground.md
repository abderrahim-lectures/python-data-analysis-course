# Playground — inline Pyodide runnable cells + notebook companions

Every lesson's code runs in the browser, on the page, with no install and no account. Three complementary surfaces:

- **Inline runnable cells** (`src/components/RunnableCell.astro` + `src/lib/runnable-cell.client.ts`): every Python code fence in a lesson is transformed (via `rehype-runnable-python.mjs`) into a cell with a ▶ Run button. Execution is **Pyodide** (Python 3 compiled to WebAssembly) loaded from the jsdelivr CDN once per page and shared site-wide.
  - _Print-wrapping_: a cell whose last statement is an expression (a bare `4 / 2`, a trailing `15`, a `type(True)`) is wrapped in `print(...)` automatically, so it echoes output the way a student expects instead of showing nothing.
  - _Friendly errors_: common beginner mistakes (syntax errors, name errors, indentation, `str()` + int, division by zero, non-numeric `int()`) are translated into plain-language hints; tracebacks are shown only when nothing matches.
  - _Datasets_: cells that reference a bundled dataset auto-mount it — `mountDatasets` reads `public/datasets/index.json`, fetches only the CSV files the page's cells name (matching under both shipped names like `students-performance.csv` and aliases like `StudentsPerformance.csv`), and writes them into Pyodide's filesystem under `/home/pyodide/` and `/`, so `open('name.csv')` works with a bare filename.
  - _Module safety_: the `js` and `pyodide` bridge modules are blocked in the cell sandbox (no `import js` escape hatch).
- **Open in full-screen editor (⛶)**: a button on every lesson cell hands the cell's code to the standalone playground page via `?code=‥` for a bigger workspace.
- **The `/playground` page** (`src/pages/playground.astro`): a byte-by-byte reuse of the inline cell markup and runtime — a big scratch editor for exploratory coding, not gated behind any lesson. `src/components/PlaygroundCell.astro` (the big freeform block) and `PlaygroundHead.astro` are shared with `404.astro`, which renders the `/playground/<code>` shared-link fallback.
- **Notebook companions**: not every student wants an in-page cell — lessons that benefit also get a generated `.ipynb` under `notebooks/<section>/<track>/<slug>.ipynb` (49 committed notebooks, generated by `scripts/generate-notebooks.mjs`) with one-click **Colab / Kaggle / nbviewer / Binder / Deepnote / GitHub** "open in" badges (`src/lib/notebookLinks.ts` builds the URLs from the repo path on `main`).

**First-load weight is a real risk on mobile data**: Pyodide (plus pandas/numpy/matplotlib wheels when a Data Analysis cell needs them) is tens of MB from the CDN. Cells show an explicit "Loading the Python environment…" state rather than a blank output area, and the Pyodide artifact is loaded once and cached by the browser service worker for that origin after the first visit. A student who never hits ▶ Run pays zero execution cost.

**Why inline cells replaced the FAB + JupyterLite**: the previous architecture used a floating action button opening dual-mode JupyterLite (REPL for Python 101, a Notebook app for Data Analysis, self-hosted under `/lite/`), and before that a Trinket.io embed. Inline Pyodide cells keep the same "zero-install, no account, self-hosted-or-CDN" property with much less machinery: no separate `/lite/` build, no iframe sandbox, and the code a student reads is the exact code they run. `jupyterlite-config/` and the deploy workflow's JupyterLite build step are now vestigial (not referenced by the site) and should be removed when CI is next touched.
