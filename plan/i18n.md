# Internationalization (i18n)

Four locales: **English** (default) plus **Arabic** (`ar`, RTL), **Spanish** (`es`), and **French** (`fr`). The site is statically prerendered per locale — no runtime fallback is needed for the chrome because every UI string ships in all four dictionaries.

## How it works (Astro)

- **UI strings** live in `messages/{en,ar,es,fr}.json` (flat `snake_case` keys), compiled by Paraglide into typed message functions in `src/paraglide/` — an unused key is tree-shaken, and a missing key fails compilation/`astro check` rather than rendering undefined. Pages pull `m.title()` / `m.nav_learn()` etc. from the compiled `m` (locale set at build time by `src/middleware.ts`).
- **Route segments** live in `src/lib/routeSegments.ts`: `detectLocale(pathname)` resolves locale from the URL, and `NAV_WORDS` + href builders produce translated paths (`/ar/تعلم`, `/es/aprender`, `/fr/apprendre`; track words too — `normal`/`hard` → `عادي`/`صعب`, `dificil`, `difficile`). Lesson/module content slugs (`python-101`, `data-analysis`) stay byte-identical across locales because they back shared `pda:state` keys. **Project URLs are the exception**: each locale serves projects under a localized slug derived from its translated `title` (see `localizedProjectSlug` in `src/lib/projectSlugs.ts`), while the English slug remains the content/gameState/art lookup key — the old English-slug routes still resolve as aliases with `rel=canonical` pointing at the localized URL.
- **Locale pages** are thin wrappers: for each locale, `src/pages/{ar,es,fr}/…/index.astro` etc. render the shared `LessonPage`/hub components with `locale` set — e.g. `src/pages/ar/تعلم/[section]/[track]/lessons/[lesson].astro` imports the EN content entry and renders it through the shared component with Arabic chrome.
- **Content**: weekly lesson/module body copy is fully translated per locale (`src/content/lessons/{ar,es,fr}/…`, `src/content/modules/{ar,es,fr}/…`, see the migration note in [`i18n-migration.md`](./i18n-migration.md)); Real-World Project pages are fully translated under `src/content/projects/{ar,es,fr}/` (lookup happens at render time by the English slug, so `relatedProjects.ts` can map lessons to projects across locales; the per-locale URL uses a slug derived from the localized title instead).
- **Per-locale notebooks**: every project page's Colab/Kaggle/Binder badges point at a notebook generated from that same locale's markdown (`examples/<slug>/notebook.{ar,es,fr}.ipynb`), so Arabic/Spanish/French learners run a notebook whose prose matches the page they're reading (code cells stay English). English keeps the hand-authored `notebook.ipynb`; the locale notebooks are produced by `scripts/generate-notebooks.mjs` and relinked by `scripts/link-project-notebooks.mjs` (idempotent, rerun-safe).
- **`<html lang>` / `dir`**: `Base.astro` sets `lang={locale}` and `dir="ltr" | "rtl"` (RTL for `ar`). `hreflang` alternate `<link>` tags and canonicals are emitted from `Base.astro` via an `alternates` prop (wired through all locale route templates), and the sitemap is locale-aware.

## Conventions

- `weekId`/module/slug values stay byte-identical across locales (they back shared `localStorage` keys). The one exception: the *URL slug* for project pages is localized per locale (URL only; the underlying project content key stays English).
- Code/identifiers/type names stay in Latin script in all translations.
- Math blocks render via KaTeX; Arabic's known glyph handling limitations in KaTeX are handled per-addition (no MathML fallback promise).
- Browser-language auto-redirect is not used in the Astro build; locale is entirely URL-driven (`/ar/…`, `/es/…`, `/fr/…`).

## Verifying

- `npm run check` (astro check) typechecks the Paraglide `messages.d.ts` + `routeSegments.ts` — a locale missing any required key fails CI.
- `tests/unit` includes a string-parity check across the four locales (EN `home*` keys etc.).
- Smoke suite (`tests/e2e/smoke.mjs`) walks the translated hubs/project pages and hreflang alternates.
