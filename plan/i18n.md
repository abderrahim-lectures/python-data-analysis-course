# Internationalization (i18n)

Four locales: **English** (default) plus **Arabic** (`ar`, RTL), **Spanish** (`es`), and **French** (`fr`). The site is statically prerendered per locale — no runtime fallback is needed for the chrome because every UI string ships in all four dictionaries.

## How it works (Astro)

- **UI strings** live in `src/lib/pageStrings.ts` as one `PAGE_STRINGS` object per locale (`en`/`ar`/`es`/`fr`), all typed by a single `PageStrings` interface so a missing key fails `astro check` rather than rendering undefined. Pages read `PAGE_STRINGS[locale]` and pull `title`, `description`, nav labels, buttons, XP/streak copy, etc.
- **Route segments** live in `src/lib/routeSegments.ts`: `detectLocale(pathname)` resolves locale from the URL, and `NAV_WORDS` + href builders produce translated paths (`/ar/تعلم`, `/es/aprender`, `/fr/apprendre`; track words too — `normal`/`hard` → `عادي`/`صعب`, `dificil`, `difficile`). Content slugs (lesson/module/project IDs, `python-101`, `data-analysis`) stay byte-identical across locales because they back shared `pda:state` keys.
- **Locale pages** are thin wrappers: for each locale, `src/pages/{ar,es,fr}/…/index.astro` etc. render the shared `LessonPage`/hub components with `locale` set — e.g. `src/pages/ar/تعلم/[section]/[track]/lessons/[lesson].astro` imports the EN content entry and renders it through the shared component with Arabic chrome.
- **Content**: weekly lesson body copy is authored once in English and shared by all locales (the chrome around it is translated); Real-World Project pages are fully translated under `src/content/projects/{ar,es,fr}/` with the same slug (lookup happens at render time by slug, so `relatedProjects.ts` can map lessons to projects across locales).
- **`<html lang>` / `dir`**: `Base.astro` sets `lang={locale}` and `dir="ltr" | "rtl"` (RTL for `ar`). `hreflang` alternate `<link>` tags and canonicals are emitted from `Base.astro` via an `alternates` prop (wired through all locale route templates), and the sitemap is locale-aware.

## Conventions

- `weekId`/module/slug values stay byte-identical across locales (they back shared `localStorage` keys).
- Code/identifiers/type names stay in Latin script in all translations.
- Math blocks render via KaTeX; Arabic's known glyph handling limitations in KaTeX are handled per-addition (no MathML fallback promise).
- Browser-language auto-redirect is not used in the Astro build; locale is entirely URL-driven (`/ar/…`, `/es/…`, `/fr/…`).

## Verifying

- `npm run check` (astro check) typechecks `pageStrings.ts`/`routeSegments.ts` — a locale missing any required key fails CI.
- `tests/unit` includes a string-parity check across the four locales (EN `home*` keys etc.).
- Smoke suite (`tests/e2e/smoke.mjs`) walks the translated hubs/project pages and hreflang alternates.
