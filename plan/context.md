# Context

Building a from-scratch university-level Python and data analysis course, hosted on GitHub Pages, covering two 5-week sections:

1. **Python 101** — fundamentals
2. **Pandas & Data Analysis** — Kaggle-style EDA

Each section offers two parallel tracks (**Normal** and **Hard**) so students can self-select difficulty. Because students won't have Python installed in the early weeks, every lesson's code runs in the browser via **inline runnable cells** (Pyodide), with a persistent **playground page** for scratch work and per-lesson notebook companions (Colab/Kaggle/Binder badges) for anyone who wants a real Jupyter environment. Students are math/data-analysis majors on their phones, not at a desk — the site and its interactions need to read that way; this also motivates the Arabic/French/Spanish/English i18n requirement below.

Decisions locked in with the user:
- **Site generator:** Astro 5 (static output) — migrated off Docusaurus 3.10.2 / React 19 in the `redesign/astro-visual-novel` branch (see [`astro-rebuild.md`](./astro-rebuild.md)).
- **Playground (inline, section-agnostic, self-hosted throughout):** every lesson's code fence becomes a runnable cell backed by **Pyodide** (Python compiled to WebAssembly, loaded from the jsdelivr CDN at runtime) — no server, no account, no external editor. Expression-only cells are wrapped in `print()` automatically and common beginner errors get friendly explanations. A standalone `/playground` page (with a ⛶ "open in full-screen editor" button on every lesson cell) is the big scratch workspace, and each lesson ships a generated `.ipynb` companion with one-click Colab/Kaggle/nbviewer/Binder/Deepnote badges for a real notebook workflow. Bundled datasets (`public/datasets/*.csv`) are served through a manifest (`public/datasets/index.json`) and auto-mounted into Pyodide's filesystem when a page's cells reference them, so `open('students-performance.csv')` just works.
  This replaced the previous design's dual-mode **JupyterLite** playground (REPL for Python 101, Notebook for Data Analysis) behind a floating action button, and before that Trinket.io (a third-party embed that could never work offline). The FAB, the `/lite/` mount, and the `jupyterlite-config` build step retired with the Astro migration.
- **Content depth:** full content for all 10 weeks × 2 tracks in this pass (not just scaffolding)
- **Languages:** English (default) plus Arabic, Spanish, and French. UI chrome (nav, footer, home, buttons, XP/streak copy) is fully translated via per-locale string dictionaries (`src/lib/pageStrings.ts`) and translated URL segments (`src/lib/routeSegments.ts` — `/ar/تعلم`, `/es/aprender`, `/fr/apprendre`); Real-World Project pages are translated under `src/content/projects/<locale>/`; weekly lesson body content is authored once in English and shared across locales. All four locales receive `hreflang` alternates and correct `<html lang>`/`dir` from `Base.astro`.
- **Pedagogy pattern:** replace plain "Exercises" with **Challenges (with revealable answers)** + **Socratic Questions** (open-ended, no-answer reflection prompts) on every lesson page
- **Client-side persistence:** since there's no backend/login, per-student state (XP, lessons/projects/challenges completed, quiz results, streaks, quests, badges, activity log) lives in the browser's `localStorage` under the single `pda:state` key (see [`persistence.md`](./persistence.md)).
- **Mobile-first, layout and performance both:** design and test every component (runnable cells, quiz, challenge blocks, playground, track comparison) at phone width first, desktop is the enhancement, not the baseline — and mobile performance (small initial bundle, heavy dependencies loaded only when actually needed) is treated as seriously as mobile layout, since this audience is on phones and often not on Wi-Fi
- **Section 1 hard track builds no numpy** — it uses only Python's built-in types, deliberately, so its performance pain becomes the motivating hook for Section 2 (see below)
- **Choosing a track is gated by information, and choosing Hard for Data Analysis is additionally gated by a self-check quiz** (see Learning Path Flow below)
- **Gamification is optional and reversible:** a badge system plus quiz-gated bonus content (try/except, classes — deliberately excluded from the core "no classes" curriculum, offered as optional extensions for students who pass a week's quiz) — but students choose **Gamified vs. Classical (minimal)** presentation up front and can flip it anytime mid-course; both modes read the same underlying progress data, so nothing is lost switching back and forth
- **Visual design/UX must be built for this specific audience** (math majors, on phones, motivated by small wins) — not a generic docs theme reskin
- **Capstone projects at the very end of the whole course, one new one added every year**: install Python locally for real (graduating off the in-browser playgrounds) and build something the playground never could. 2026's is a first AI agent with LangChain's `deepagents`, using a free-tier AI API — students are free to pick whichever provider they like (GitHub Models is the suggested default, no separate signup, ties into the GitHub account every student already has; Gemini, Groq, Mistral, Cerebras, and OpenRouter are documented alternatives). Past years' Capstones stay available alongside the newest one, so a student picks whichever project sounds most interesting, not just whatever's current. This is teased on the welcome page's learning-objectives summary from day one as motivation to finish, not sprung on students at the end — see the dedicated Capstone Projects section below.

## Provenance

This design plan started as a single `PLAN.md` at the repo root, copied in from the original plan-mode approval before any code existed. It later grew to 22+ sections as the course was built out, and was split into this `plan/` folder (one file per section, `plan/README.md` as the index) once it became too large to review or link into precisely as one file.
