# Progressive Web App (PWA)

Fits the course's "no installs, on your phone" framing — the site is installable and the key pages work offline after a first visit, without any external service:

- `public/manifest.json`: name/short_name, display `standalone`, theme/background colors, and 192/512 icons (rendered from the logo). Wired from `src/layouts/Base.astro` `<link rel="manifest">`.
- `public/sw.js`: a hand-written service worker (no plugin — the Astro build has no PWA dependency). It precaches the core routes (`/`, `/learn`, `/playground`, `/progress`, `/projects`) on install, then on `fetch`: **network-first for navigations** (fresh course content always wins over the cache; the cached page is only an offline fallback), and stale-while-revalidate for same-origin assets. Cross-origin requests (the Pyodide CDN) are never touched. Skips waiting, claims clients, and deletes any cache other than the current versioned one on activation — bump `CACHE_NAME` to force a clean re-precache. Registered from `Base.astro`'s head script. This makes the app shell work offline for every visitor after the first successful load, matching the "works offline once you've visited a page" pitch, while keeping returning learners on the latest content.
- There is no `beforeinstallprompt` install button in the current build (the old Docusaurus `InstallPwaButton` was not carried over) — browsers' native install affordances still apply via the manifest.
- **Offline caveat, Pyodide is CDN-loaded**: lesson pages render offline, but *running* a cell needs Pyodide (loaded from the jsdelivr CDN at runtime, tens of MB on first use). A browser that has executed a lesson before will have the Pyodide artifacts in HTTP cache and can re-run offline; a brand-new offline visit can read the lesson but cannot execute cells until it has network. This is a known trade-off of the inline-cell runtime, not a regression.
